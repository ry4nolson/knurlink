#random · Slack
    click a link. press 1–9, A for always, esc to cancel.

    how it decides

    1. 1

      you click a link

      in Slack, Mail, a terminal, wherever. macOS hands it to knURLink because it's your default browser.

    2. 2

      rules get first dibs

      if a rule matches, the link goes straight to that browser or profile. no popup, no decision.

    3. 3

      otherwise, bubbles

      nothing matched, so a ring of bubbles opens at your cursor. pick one. tick "always" and you won't be asked again.

    the picker

    one bubble per browser, and one per profile for Chromium browsers and Safari. it opens wherever your cursor is and gets out of the way the moment you choose.

    "always" checkbox

    tick it in the hub, or press A, and knURLink saves a domain rule on the spot. it saves the site, not the subdomain: news.ycombinator.com saves ycombinator.com, and bbc.co.uk keeps its .co.uk.

    hide what you don't use

    Browsers in settings lists every browser and profile it found. turn off the ones you never pick. hiding only takes a bubble out of the picker. rules can still send links there.

    rules

    a rule is a link pattern, an optional app it came from, and where it opens. links that match skip the picker.

    domain tiktok.com
    • tiktok.com
    • www.tiktok.com
    • tiktok.com/@rickastleyofficial
    • nottiktok.com

    covers every subdomain. *.tiktok.com works too, if that's how your brain types it.

    path github.com/ry4nolson
    • github.com/ry4nolson
    • github.com/ry4nolson/knurlink
    • github.com/ry4nolson-fork
    • github.com/apple/swift

    matches that path and everything under it, on whole path segments.

    source app any link from Mail
    • anything you click in Mail
    • the same link from Slack

    leave the link blank and pick an app to route everything it sends. fill in both to scope a domain to one app.

    private youtube.com · private
    • opens in incognito or a private window

    turn on Private for a rule and its matches open privately, every time. see which browsers support it.

    when more than one rule matches

    the most specific link wins. in order:

    1. longer domain. api.github.com beats github.com.
    2. then longer path. github.com/ry4nolson beats github.com.
    3. then app-scoped. a rule for links from Slack beats the same rule for any app.
    4. still tied? the one higher in your list.

    a rule with no link has no domain length, so it's the fallback. matching ignores case, https://, www., ports, query strings, and #fragments.

    test a link

    settings has a Test a Link pane. this is that, running the same matching logic ported to the browser. paste a link, pick where it came from, and see which rule wins and which ones matched but lost. the rules underneath are editable, and the demo up top uses them too.

    safari profiles

    macOS has no way to launch a Safari profile. so knURLink does it the long way.

    1. it uses the Accessibility API to pick the profile's "New Window" item from Safari's File menu.
    2. it hands that new window the link.
    3. if anything goes wrong, the link opens in plain Safari. you still get your page.

    it asks for Accessibility access under Browsers in settings. profile names are read from Safari's menu while it's running and remembered after that, so Safari needs to have run once with knURLink open. it reads the English menu titles, so other macOS languages won't find them yet.

    the rest

    make default

    open the app, click Make Default, and confirm the macOS prompt. after that it lives behind the menu bar icon.

    launch at login

    a toggle in General, off by default. it starts quietly in the menu bar. no window in your face at 9am.

    update check

    the About section tells you when there's a new release and links to the download. it never installs anything on its own. turn it off if you'd rather it didn't ask.

    nothing leaves your mac

    your links and rules stay local. the one network call is the update check, a single request to GitHub's releases API.

    your rules are plain JSON

    saved to ~/Library/Application Support/Knurlink/config.json. edit it by hand if you like. quit the app first, or it'll overwrite your edits. id is optional when you write rules yourself.

    {
  "rules": [
    { "pattern": "tiktok.com",
      "target": { "bundleID": "com.brave.Browser" } },
    { "pattern": "github.com/my-org",
      "target": { "bundleID": "com.google.Chrome",
                  "profileDirectory": "Profile 1" } },
    { "pattern": "", "sourceBundleID": "com.apple.mail",
      "target": { "bundleID": "com.apple.Safari" },
      "opensPrivately": true }
  ],
  "checksForUpdates": true
}

    install

    1. grab knURLink.dmg from the latest release.
    2. drag the app to Applications and open it.
    3. click Make Default. macOS will ask you to confirm.

    release builds are signed and notarized. it needs macOS 14 or later.

    Download for Mac

    or build it yourself

    you need Xcode or the Swift toolchain, Swift 5.9 or newer.

    git clone https://github.com/ry4nolson/knurlink
cd knurlink
./scripts/build-app.sh --install

    that builds a release binary, wraps it in knURLink.app, ad-hoc signs it, and copies it to /Applications. leave off --install to just get dist/knURLink.app. run the tests with swift test.

    limits

    • profiles are detected for Chromium browsers (Chrome, Brave, Edge, Vivaldi, Chromium) and Safari. Firefox shows up as one bubble.
    • source app rules depend on macOS reporting who sent the link. links opened with open from a terminal come through with no sender.
    • Safari profiles need Accessibility access and English menu titles.
    • local builds are ad-hoc signed unless you name an identity. only tagged releases are notarized.

    the name is a knurl, the grip pattern you cut into a tool handle, with a url hiding in it.
